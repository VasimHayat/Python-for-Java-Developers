Collections are protocols plus literals

Python's core collections are built into the language's syntax and idioms.

Lists, dicts, sets, and tuples cover much of what Java developers reach for with collection classes. The important shift is operations: slicing, membership, unpacking, and comprehensions are normal code, not clever code.

Java
Map<String, Integer> counts = new HashMap<>();
counts.merge("ok", 1, Integer::sum);
Python
counts: dict[str, int] = {}
counts["ok"] = counts.get("ok", 0) + 1
Idiomatic Python
Python
names = ["ada", "grace", "guido"]
initials = {name[0].upper() for name in names}
index = {name: len(name) for name in names}
print(initials, index)
Coming from Java: Unlearn creating wrapper classes for every small mapping. A plain dict with clear names is often the Pythonic domain object at the boundary.
Under the hood

dict preserves insertion order as a language guarantee in Python 3.7+. Do not rely on hash-table ordering semantics beyond that guarantee.

Comprehensions beat most stream pipelines

Python comprehensions are the local, readable form of map/filter/collect.

Java Streams make collection transforms fluent. Python comprehensions keep the shape close to the data. Use them for straightforward transforms and switch to generator expressions when you want laziness.

Java
List<String> shortNames = names.stream()
    .filter(n -> n.length() < 5)
    .map(String::toUpperCase)
    .toList();
Python
short_names = [n.upper() for n in names if len(n) < 5]
Idiomatic Python
Python
names = ["ada", "grace", "guido"]
total = sum(len(n) for n in names if "a" in n)
print(total)
Coming from Java: Unlearn turning every transform into chained method calls. Python's for expression is the idiom.
