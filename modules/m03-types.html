The Type System

A Java-first bridge into the Python mental model, with runnable CPython 3.12 examples.

Gradual typing, not Java typing with fewer keywords

Type hints describe intent for tools; CPython does not enforce them at runtime.

Python's type system is dynamic and duck-typed. Hints let pyright or mypy catch many errors, but runtime behavior still follows objects and protocols. Treat hints as executable documentation for humans and static analyzers.

Java
List<String> names = List.of("Ada", "Guido");
String first = names.getFirst();
Python
names: list[str] = ["Ada", "Guido"]
first: str = names[0]
Idiomatic Python
Python
from collections.abc import Iterable

def total_lengths(names: Iterable[str]) -> int:
    return sum(len(name) for name in names)

print(total_lengths(["Ada", "Guido"]))
Coming from Java: Unlearn believing the annotation makes a runtime guarantee. Validate external input; annotate internal contracts.
Under the hood

Since Python 3.9, built-in generics like list[int] are standard. Use from __future__ import annotations only when you need postponed evaluation patterns.

None is not Optional

Optional means the value may be None; it does not mean the parameter is optional.

Java Optional is a wrapper. Python uses None directly for absence, and defaults determine whether an argument can be omitted. A parameter typed str | None but lacking a default is still required.

Java
Optional<String> nickname = Optional.empty();
String label = nickname.orElse("anonymous");
Python
nickname: str | None = None
label = nickname if nickname is not None else "anonymous"
Idiomatic Python
Python
def greet(name: str | None = None) -> str:
    display = name if name is not None else "anonymous"
    return f"Hello, {display}"

print(greet())
Coming from Java: Unlearn wrapping absence just to look explicit. Python's explicitness is in the branch, not an Optional container.
