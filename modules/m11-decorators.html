A Java-first bridge into the Python mental model, with runnable CPython 3.12 examples.

Decorators execute at definition time

Decorators execute at definition time

A decorator is executable wrapping code, closer to a tiny AOP function than a Java annotation.

Java
// Java-shaped baseline
var items = List.of("ada", "grace", "guido");
var result = items.stream()
    .filter(s -> s.length() > 3)
    .map(String::toUpperCase)
    .toList();
Python
import functools

def logged(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        print(f"calling {fn.__name__}")
        return fn(*args, **kwargs)
    return wrapper
Idiomatic Python
Python
import functools

def repeat(times: int):
    def decorate(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = fn(*args, **kwargs)
            return result
        return wrapper
    return decorate

@repeat(2)
def hello() -> None:
    print("hi")

hello()
Coming from Java: Unlearn translating Java structure one-to-one. Preserve the intent, then choose the Python mechanism that makes that intent smallest and clearest.

Naive translation vs Pythonic design

Correct Python can still be Java wearing Python syntax.

The expert move is not merely making code run. It is removing patterns Python does not need: manager classes with no state, premature interfaces, getter/setter grids, LBYL checks before every operation, and stream-shaped code where a comprehension says the same thing.
