Functions are first-class configuration

Python often passes behavior directly instead of manufacturing strategy classes.

A Python function is an object with a name, attributes, and a type. That makes callbacks, key functions, decorators, and dependency injection lightweight. Reach for a class when you need state plus behavior, not just because Java would name an interface.

Java
users.sort(Comparator.comparing(User::lastName));
Python
users.sort(key=lambda user: user.last_name)
Idiomatic Python
Python
def by_domain(email: str) -> str:
    return email.split("@", 1)[1]

emails = ["a@z.dev", "b@example.com"]
print(sorted(emails, key=by_domain))
Coming from Java: Unlearn creating a one-method class for every behavior slot. A function is already a good abstraction.

Defaults are evaluated once

Python default arguments are bound when the function is defined, not each time it is called.

Java defaulting usually happens inside the method body or through overloads. Python defaults live on the function object. Immutable defaults are fine; mutable defaults become shared state.

Java
void add(String value) {
    List<String> items = new ArrayList<>();
    items.add(value);
}
Python
def add(value: str, items: list[str] | None = None) -> list[str]:
    if items is None:
        items = []
    items.append(value)
    return items
Idiomatic Python
Python
def append_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    tags = [] if tags is None else tags
    tags.append(tag)
    return tags

print(append_tag("fast"))
Coming from Java: Unlearn using [] or {} as a default unless shared state is exactly what you intend.
Under the hood

Function default values are stored in func.__defaults__, which is why mutation persists.
